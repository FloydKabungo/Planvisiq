**How the export feature should work**

The user should be able to choose:

| Export setting   | Options                                                                     |
| ---------------- | --------------------------------------------------------------------------- |
| **Scope**        | Whole project, selected areas, disciplines, contractors or work packages    |
| **Period**       | Shift, day, week, month, custom dates or entire project                     |
| **Comparison**   | Original baseline, approved revised baseline, previous period or target     |
| **Detail**       | Executive summary, detailed report or supporting records                    |
| **Presentation** | Company logo, client name, project title, colours and cover page            |
| **Contents**     | Selected charts, tables, commentary, photos and attachments                 |
| **Format**       | PDF, PowerPoint, Excel, CSV or a combined ZIP package                       |
| **Traceability** | Reporting cut-off, source files, units, calculation definitions and version |

**Build these as reusable report templates on top of shared datasets.** For example, the same progress records can feed the Executive Progress Report, Daily Progress Report, S-Curve Report and Final Close-Out Report.

Some outputs need richer information: a critical-path report needs schedule logic and calendars; earned value needs an agreed baseline and progress valuation method; readiness reports need recorded checks and approvals. Your app should flag missing inputs and preserve the distinction between **reported status and authorised approval**.
